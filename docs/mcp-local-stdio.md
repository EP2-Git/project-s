# Local MCP over stdio

Project S's first MCP transport is a local, client-launched Node process. It exposes the same four public-booking operations as the HTTP API and SDK. It never imports Supabase, opens a database connection, or uses a service-role key.

## Prerequisites

- Node.js 22.12 or newer.
- A running Project S HTTP API that implements contract version 1.
- `PROJECT_S_API_BASE_URL` set to the origin that serves Project S's `/api/v1` routes. HTTPS is required except for loopback development URLs. During `npm run dev`, use `http://127.0.0.1:8080`; Vite proxies those routes to the local Edge Function.

Do not put a Supabase service-role key, database password, or guest information in the MCP process environment. These four operations are the public guest-booking surface; authorization, confirmation, rate limiting, audit, and scheduling authority remain server-side.

## Launch

From the repository root:

```powershell
$env:PROJECT_S_API_BASE_URL = "http://127.0.0.1:8080"
node packages/mcp-server/src/bin.mjs
```

The root workspace exposes the same command as `npm run mcp:stdio`. MCP clients should configure that command as a subprocess and supply only `PROJECT_S_API_BASE_URL`.

The process uses newline-delimited JSON-RPC over standard input and standard output. Standard output is protocol-only. Operational diagnostics go to standard error and contain only the operation name, stable error code, and request ID—not tool arguments, guest details, tokens, or raw thrown errors.

## Behavior

- Protocol revision: `2026-07-28`.
- Transport: local stdio only.
- Discovery: `server/discover`.
- Capability: tools only, with a deterministic four-tool list.
- State: stateless; every request supplies its protocol version and client capabilities in `_meta`.
- Protocol request cancellation: `notifications/cancelled` aborts an in-flight
  SDK request and suppresses a later response. It does not cancel a booking;
  booking cancellation is an authenticated host-only contract outside MCP v1.
- Maximum message size: 1 MiB.
- Tool schemas: JSON Schema 2020-12 generated by `@project-s/contracts`.

This server intentionally does not implement the legacy `initialize`-session era. A legacy-only client receives an actionable error naming the supported modern revision.

## Confirmation is outside the MCP process

`project_s_prepare_booking_v1` returns a short-lived preparation and browser confirmation URL. Preparation does not reserve a slot. A human must approve the exact derived booking in Project S's browser flow. Only the API may record that approval and authorize `project_s_create_booking_v1`; a model assertion such as `confirmed: true` is not accepted by the contract.

See [agent-confirmation-flow.md](agent-confirmation-flow.md) for the complete state transition.

## Verification

Run the dependency-free protocol suite:

```powershell
node --test packages/mcp-server/tests/*.test.mjs
```

Before release, also run the pinned official MCP conformance requirements set for `2026-07-28`, the shared Project S transport-parity vectors, and the repository's full check workflow. A unit-test pass alone is not publication evidence.
