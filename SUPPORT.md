# Project S support

Project S Core is public pre-alpha software. There is no production support,
service-level agreement, compatibility guarantee, or hosted Project S support
desk.

## Where to go

| Need | Public route |
| --- | --- |
| Reproducible defect | [Bug report](https://github.com/EP2-Git/project-s/issues/new/choose) |
| Evaluation friction | [Evaluation feedback](https://github.com/EP2-Git/project-s/issues/new/choose) |
| Incorrect or missing documentation | [Documentation issue](https://github.com/EP2-Git/project-s/issues/new/choose) |
| Usage question | [Discussions Q&A](https://github.com/EP2-Git/project-s/discussions) |
| Uncommitted product idea | [Discussions Ideas](https://github.com/EP2-Git/project-s/discussions) |
| Accepted actionable work | [Issues](https://github.com/EP2-Git/project-s/issues) |
| Contract or authority design | [RFC/design proposal](https://github.com/EP2-Git/project-s/issues/new/choose) |
| Accessibility barrier | [Accessibility issue](https://github.com/EP2-Git/project-s/issues/new/choose) |
| Vulnerability | [Private vulnerability report](https://github.com/EP2-Git/project-s/security/advisories/new) |

Do not put credentials, capability URLs, private environment values, real
bookings, names, emails, or production identifiers in a public Issue,
Discussion, or pull request. Reproduce with the synthetic local fixture.

## What maintainers can reasonably help with

Maintainers may clarify documented local setup, evaluate reproducible defects,
and review focused changes. They cannot promise deployment advice for an
internet-facing service, data recovery, incident response, regulatory
compliance, custom integration work, or response times.

Before asking for help, check [local development](docs/local-development.md),
[self-hosting](docs/self-hosting.md), [testing](docs/testing.md), and the
[documentation index](docs/README.md).
